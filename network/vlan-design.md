# ネットワーク・VLAN設計

## 物理構成

```
[Commufa Hikari ONU]
        │
        ▼
[NEC IX2215]
  WAN: PPPoE接続
  LAN: 802.1Qトランクポート → スイッチへ
        │
        ▼
[Allied Telesis スイッチ]
  ├── Port 1-8  : VLAN10 (Access) → サーバー
  └── Port 9-16 : VLAN20 (Access) → クライアントPC
```

## VLAN定義

| VLAN | 名前 | サブネット | ゲートウェイ | 用途 |
|------|------|-----------|-------------|------|
| 10 | SERVER | 192.168.10.0/24 | 192.168.10.1 | Proxmoxノード・各VM |
| 20 | CLIENT | 192.168.20.0/24 | 192.168.20.1 | 開発PC・端末 |

## VLAN間ルーティングポリシー（IX2215 ACL）

| 方向 | 許可/拒否 | 理由 |
|------|----------|------|
| CLIENT → SERVER (特定ポートのみ) | ✅ 許可 | Webサービス閲覧・SSH(Tailscale経由) |
| CLIENT → SERVER (その他) | ❌ 拒否 | 不正アクセス防止 |
| SERVER → CLIENT (自発通信) | ❌ 拒否 | サーバー侵害時の横展開防止 |
| SERVER → Internet | ✅ 許可 | パッケージ更新・外部API |
| CLIENT → Internet | ✅ 許可 | 通常のインターネットアクセス |

## 設計の意図

### なぜVLAN分離したか
開発環境では自分のPCからサーバーへアクセスする機会が多いが、
クライアントセグメントで何か問題が起きてもサーバーに影響しないよう分離した。
実際にマルウェア等でクライアントが侵害された場合でも、
VLAN ACLによってサーバーセグメントへの横移動を防げる。

### Tailscale VPNを採用した理由
- 外部から管理したいが、SSHポートを直接インターネットに公開したくない
- Cloudflare Tunnelはゲームサーバー（UDP）に非対応
- WireGuardを自前管理するより、Tailscaleのコントロールプレーンを利用する方が
  鍵管理・ACL管理のコストが低い
- ゼロコスト（個人利用はFreeプランで十分）
