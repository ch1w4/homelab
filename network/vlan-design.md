# ネットワーク・VLAN設計

> 最終更新: 2026-11-13

## 物理構成

```
[コミュファ光 ONU]
        │
[Aterm WH832A]  PPPoE ブリッジ ＋ 家族用 Wi-Fi（1階）
        │ 約20m（Cat6a）
[ハブ TL-SG105]  ── PPPoE と家族用 LAN を 2 台のルーターで共有（port5 → #1、port2 → #2）
   │                              │
[NEC IX2215 #1] ◀── VRRP ──▶ [NEC IX2215 #2]
   │ GE2 port5〜8（静的 LAG）      │ GE2 port5〜8（静的 LAG）
[Allied Telesis AT-x210-24GT]
   ├── port1〜4   : sa2（IX2215 #2 との LAG）
   ├── port5〜8   : access VLAN10（PC）
   ├── port9      : access VLAN50（検証）
   ├── port17〜19 : trunk VLAN 20/30/50/99 → Proxmox ①②③
   ├── port20     : trunk VLAN 10/50/60/99（すべてタグ付き）→ TL-SG1005P（PoE）→ 無線 AP
   └── port21〜24 : sa1（IX2215 #1 との LAG）
```

- Aterm は PPPoE ブリッジにして、IX2215 が直接 PPPoE を張る（NAT は 1 段）。
- 各 Proxmox ノードは LAN ポート 1 本を trunk にし、`vmbr0`（VLAN-aware）でタグを見て VM に振り分ける。

## VLAN 定義

| VLAN | 名前 | サブネット | ゲートウェイ | IX の口 | 用途 |
|---|---|---|---|---|---|
| — | 家族 | 192.168.0.0/24 | 192.168.0.254 | GE0.0 | 家族用 LAN |
| 10 | 一般 | 192.168.10.0/24 | 192.168.10.1 | GE2.10 | 自分の PC・SSID lab |
| 20 | サーバー | 192.168.20.0/24 | 192.168.20.1 | GE2.20 | DB・Git・VPN・監視・バックアップ |
| 30 | DMZ | 192.168.30.0/24 | 192.168.30.1 | GE2.30 | 外部公開（proxy01・mc01） |
| 50 | 検証 | 192.168.50.0/24 | 192.168.50.1 | GE2.5 | テスト VM・SSID test |
| 60 | ゲスト | 192.168.60.0/24 | 192.168.60.1 | GE2.6 | SSID guest（インターネットだけ） |
| 99 | 管理 | 192.168.99.0/24 | 192.168.99.1 | GE2.9 | Proxmox・スイッチ・IX・AP の管理 |

ゲートウェイはすべて VRRP の仮想 IP。IX の実 IP は #1 が `.252`、#2 が `.253`（家族用は `.2`／`.3`）。VRID は VLAN 番号と同じ（家族用は 1）。

IX2215 のサブインターフェース番号は 0〜32 までのため、VLAN50 は GE2.5、VLAN60 は GE2.6、VLAN99 は GE2.9 にしている（タグの VLAN ID は 50・60・99 のまま）。

## VLAN 間フィルタ（IX2215）

| 方向 | 許可/拒否 | 理由 |
|---|---|---|
| 一般（10）→ 全 VLAN | ✅ 許可 | 自分の PC から管理する |
| DMZ（30）→ サーバー（20） | 必要なポートだけ許可（DB、mc01 → vpn01 の返事 25565/tcp・19132/udp など） | 公開サーバーが乗っ取られたときの横展開を防ぐ |
| DMZ（30）→ その他の内部 | ❌ 拒否 | 同上 |
| 管理（99）→ 他 VLAN | ❌ 拒否（監視・ログ送信など必要なものだけ許可） | 管理系を他から切り離す |
| 家族 → ラボの各 VLAN | ❌ 拒否 | 家族の端末からラボに入れないようにする |
| ゲスト（60）→ 内部すべて | ❌ 拒否（DHCP・DNS だけ許可） | ゲストはインターネットだけ |
| 各 VLAN → インターネット | ✅ 許可 | 更新・外部 API |
| インターネット → 内部 | ❌ 拒否（動的フィルタで戻りの通信だけ通す） | 外から入れる口を作らない |

## 冗長化

- **IX2215 ⇔ スイッチ**：2台とも 4 本の静的 LAG（IX は LACP 非対応）。1〜3 本切れても通信が続く。スイッチ側の sa1・sa2 は edgeport（IX は STP を話さないので、つないだ直後に止まらないようにする）。
- **ゲートウェイ**：IX2215 2台で全 VLAN と家族用 LAN を VRRP。#1（優先度 200）が止まると #2（100）が約 3 秒で引き継ぐ。preempt は2台とも切っている。
- **PPPoE**：コミュファは同じ ID で 2 セッションまで張れるので、2台とも常時接続。#1 が急に止まると回線側に古いセッションが残り、復帰した #1 はしばらくつながらない。#1 の PPPoE がつながってから #2 を再起動して戻す。
- **DHCP**：範囲を前半（#1）・後半（#2）に分けて、2台とも配る。

## 無線 AP

- BUFFALO WAPM-1166D（管理 192.168.99.30・管理 VLAN 99）。SSID：lab → VLAN10、test → VLAN50、guest → VLAN60（端末どうしの通信は禁止）。
- 有線ポートは **Tagged**（99・10・50・60 すべてタグ付き）。「Multiple」（管理だけタグなし）にすると AP の中で VLAN が混ざり、VLAN10 のゲートウェイに届かなくなったため使わない。

## 外部公開と管理アクセス

### Web：Cloudflare Tunnel
proxy01（DMZ）の cloudflared が Cloudflare に外向きでつなぎ、Nginx Proxy Manager から各アプリへ振り分ける。ルーターでポートを開けない。

### Minecraft：Oracle Cloud の中継サーバー
Cloudflare Tunnel はゲーム（TCP/UDP の生ポート）を通せないため、Oracle Cloud（Always Free・大阪）に relay01 を置いた。

```
プレイヤー → relay01 ─┬ TCP 25565 → HAProxy（PROXY protocol v2）─┐
                      └ UDP 19132 → iptables DNAT              ─┤ Tailscale
                                                                └→ vpn01 → mc01（Velocity）
```

- Tailscale の ACL で、relay01（`tag:relay`）が届くのは mc01 の 2 ポートだけ。
- Velocity 側は `haproxy-protocol = true`、Geyser も Velocity への接続で PROXY protocol を使う。
- vpn01 は Tailscale の通信を自分の IP（192.168.20.15）に書き換えて mc01 に送る（SNAT）。vpn01 は VLAN20 にいるので、mc01 の返事は IX を通る。そのため IX の dmz-in に、mc01（25565/tcp・19132/udp）→ 192.168.20.15 の許可が必要。

### 管理：Tailscale
vpn01（LXC）をサブネットルーターにして、VLAN 20/30/50/99 に外から入れるようにしている。SSH や管理画面はインターネットに一切出さない。

## 設計の意図

### なぜ VLAN を細かく分けたか
「公開するもの（DMZ）」「内部サービス（サーバー）」「管理（99）」「自分の端末（10）」「家族」で信頼度が違うため。公開サーバーや家族の端末に何かあっても、管理系や DB まで届かないようにしている。

### なぜ自宅の IP を出さないか
DNS は誰でも引けるので、自宅の IP を向けるとそのまま攻撃対象になる。Web は Cloudflare Tunnel、ゲームは中継サーバー経由にして、自宅側はポートを開けない構成にした。

### Tailscale を使う理由
- SSH や管理画面をインターネットに出さずに外から管理できる
- WireGuard を自前で管理するより、鍵・ACL の管理が楽
- ACL のテスト機能で「中継サーバーから SSH や DB に入れない」ことを保存のたびに確認できる
